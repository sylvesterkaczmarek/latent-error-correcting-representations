# Research integrity audit

## Candidate

Version 0.2.0rc1 is an unpublished implementation candidate, prepared 5 November
2026 from base commit 5c59cca. Independent review, merge and release remain separate.
The original suite passed 214 tests. A new external audit file reproduced 22
failures before correction; the original probe file and before/after logs remain
in the local review evidence. These are implementation checks, not outside
certification or certification of model safety.

## Corrections

| Finding | Correction |
| --- | --- |
| Decoder repair arguments accepted truthy strings, integers and None. | Require explicit boolean controls in all three existing decoder functions. |
| Correction metrics accepted repairs with no corresponding detection. | Validate detector/repair consistency and device identity before calculating rates. |
| Summaries accepted contradictory bit/task accuracies, more repairs than detections, nonfinite losses and unexpected methods. | Validate the complete comparison and rate relationships before aggregation. |
| Dictionary comparison treated numeric/boolean metadata aliases as equivalent. | Compare canonical finite JSON representations and validate key configuration types. |
| Returned summary metadata was still a mutable reference to an input run. | Own a detached metadata snapshot. |
| CLI reruns could overwrite the checked summary or leave mixed experiments. | Require a new directory, record a plan, preserve failures and publish a completion manifest only on success. |
| A seed-level output collision was checked only after training. | Reject an existing seed record before RNG changes; atomically publish complete finite JSON without replacement. |

A later numeric control also confirms that an unrepresentable learning rate fails
with a defined input error before model changes. Existing exhaustive Hamming,
repetition and attack tests remain intact. Sparse/non-strided bit tensors now
produce a defined validation error instead of an unsupported-operation failure.

## New controlled comparison

The separate selective-decoding study adds classical SECDED and detection with
abstention, integer-denominator outcome metrics, code-rate accounting, three/four-
bit stress tests, paired seed statistics and full decision traces. It does not
change the four-method historical registry or original corruption random streams.
See selective-decoding.md for executed results and their limitations.

Five original-method runs at the candidate exactly matched the five baseline
seed records, including encoder metrics and both accuracy references. A repeated
five-seed selective study matched every non-timing record and model checkpoint.
The original summary and reference configuration are preserved unchanged.

## Output and compatibility contract

Command names and original method/metric paths remain. Repair flags must now be
True or False. Summaries reject structurally inconsistent records. Existing complete
legacy run records can still be summarized together, with original standard-
deviation conventions; mixing old/new metadata remains invalid.

All experiment commands require an absent output directory. In particular, the
old `--out results` command refuses the tracked results directory. Updated quick-
start commands use `runs/reference`. Choose a new directory for another run; old
results are never automatically deleted. A directory with plan/failure evidence
but no completion.json is incomplete. Filesystem hard-link publication must be
supported; unsupported filesystems fail explicitly. These controls are not a
transactional database, hostile-directory sandbox or full crash-durability claim.

The neural reference requirements record the actual CPython 3.13 macOS runtime
closure. They are not a cross-platform hash lock. CI separately resolves the
supported Python versions and tests the complete installed package.
